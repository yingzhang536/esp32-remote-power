# ESP32 远程开机控制器 · 接线说明（测试阶段 1）

> 项目：ESP32 远程开机控制器（仓库根 README.md）
> 固件：PC_PowerRelay.ino（同目录）
> 本阶段只做**离线硬件测试**，不接主板。

## 一、物料

| 序号 | 名称 | 数量 | 说明 |
|---|---|---|---|
| 1 | ESP32 DevKitC | 1 | 主控 |
| 2 | 5V 光耦隔离继电器模块 | 1 | 低电平触发，NO/COM 触点模拟按键 |
| 3 | 杜邦线 | 若干 | 母对母 |
| 4 | 独立 5V 手机充电器（推荐） | 1 | 给 ESP32 供电，避免吃主板 S5 待机电流 |

## 二、ESP32 ↔ 继电器接线（信号侧）

| 继电器引脚 | → ESP32 引脚 |
|---|---|
| VCC | 5V（板载输出） |
| GND | GND |
| IN（信号脚） | GPIO4 |

> ⚠️ **低电平触发**：套件继电器 IN=LOW 吸合、IN=HIGH 断开。
> 固件上电默认 GPIO4 输出 HIGH → 继电器断开（安全态，不会一上电就触发）。
> 触发时固件拉低 0.4s → 吸合 → 恢复 HIGH → 断开。

## 三、引脚选择说明

- 固件用的是 **GPIO4**（非 strapping 引脚，避开上电采样干扰）。
- 如需再换：GPIO16 / GPIO17 / GPIO18 也可以，改固件 `#define RELAY_PIN 4` 一行 + 接线即可。

## 四、测试阶段 1 步骤（离线，不接主板）

1. **接线**：按第二节接好 ESP32 ↔ 继电器。
2. **烧录**：Arduino IDE 打开 PC_PowerRelay.ino，选板 ESP32 Dev Module、COM 口，改好 WiFi/ECS IP 配置，上传。
3. **串口监视器**（115200）观察：
   - 上电后确认继电器**不吸合**（无"咔哒"声、NO-COM 不通）——固件 HIGH 默认态 ✅
   - WiFi 连上、MQTT 连上、订阅成功日志 ✅
4. **本地发 trigger**：需要一个 MQTT 工具（如 PC 上 mosquitto_pub，或手机 MQTT 调试 App）向 `device/pc_power` 发 `trigger`：
   ```
   mosquitto_pub -h <ECS公网IP> -t device/pc_power -m trigger
   ```
   观察：继电器吸合"咔哒"一声，约 0.4s 后释放；串口打印 `[TRIGGER] 收到 trigger...` ✅
5. **冷却验证**：10s 内连发 2-3 次 trigger，只有第一次有动作，后续打印 `[IGNORE] 冷却中...` ✅
6. **断电重启**：拔电重上电，确认继电器保持断开，不会误触发 ✅

## 五、安全要求（需求文档 2.4，焊主板阶段才涉及）

1. 焊接主板前**必须拔掉台式机电源线**，释放主板残余电压。
2. 继电器触点只接主板电源按键**无源引脚**（COM/NO），不接任何强电。
3. 焊接前先脱离主板完成本阶段测试，确认继电器动作正常再上机。

## 七、真实主板接法（最终版，2026-09-15 定稿 ✅ 已实测）

> **2026-09-15 真实环境验证通过**: PB-EPWR 两个针脚直接接继电器 COM/NO(LED 测试电路并联未拆), ECS 执行命令实测开机 2-3 次成功。

```
信号侧（ESP32 → 继电器）:
  继电器 VCC ──→ ESP32 5V
  继电器 GND ──→ ESP32 GND
  继电器 IN  ──→ ESP32 GPIO4

负载侧（继电器 → 主板电源键）:
  继电器 COM ──→ 主板电源键焊点 ①
  继电器 NO  ──→ 主板电源键焊点 ②
  (COM/NO 无极性, 不分正反)
```

**要拆掉的（LED 测试残留）**
- 3V3 → 220Ω → LED → COM 整条（LED、电阻、3V3 线全拆）
- 继电器 NO → GND 那根（给 LED 回路用的）

**三个关键点**
1. 并联不串联：保留机箱电源键排线（PWR_SW），COM/NO 与它**并联**——继电器吸合=按下电源键，物理按键仍可用
2. 断电操作：接主板前拔掉电脑电源线+关机（需求文档 2.4）
3. 独立供电：ESP32 接专用 USB 电源（电脑关机后 USB 无电）

**使用流程**：电脑关机 → ESP32 独立供电待命 → 人在外面 ssh ECS 跑 `send_power_cmd.py` → 继电器吸合 0.4s → 开机

## 八、LED 测试版接法（用 LED 模拟电脑电源键，2026-09-15 已实测通过 ✅）

> 场景：继电器不接主板前，用 LED 当"电脑电源键"的可视化替代，验证 开发板→继电器→负载 全链路。
> 原理：LED 串在 3V3 和 COM 之间、NO 接地——继电器吸合(COM-NO 导通)时 LED 亮 0.4s = 模拟按电源键。
> **2026-09-15 实测：上电不误触发 ✅ / trigger 吸合 0.4s ✅ / 冷却生效 ✅**

**⚠️ 关键坑（本模块实测）：3.3V 驱动 5V 低电平触发模块**
- 实测：模块 IN 悬空=断开、碰 0V=吸合、**碰 3.3V 也吸合**（5V 供电下 3.3V 仍算低电平，光耦照常导通）
- 解决：**GPIO4 用开漏模式**（固件 `pinMode(RELAY_PIN, OUTPUT_OPEN_DRAIN)`）
  - `digitalWrite(HIGH)` = 高阻悬空 → 继电器断开
  - `digitalWrite(LOW)` = 0V → 继电器吸合
- 这就是 3.3V 单片机驱动 5V 继电器模块的经典坑，普通推挽输出（3.3V HIGH）无法让模块断开

**信号侧（开发板 → 继电器）**
| 继电器引脚 | → 接 |
|---|---|
| VCC | ESP32 5V 引脚 |
| GND | 面包板蓝轨（GND 轨，连 ESP32 GND） |
| IN | ESP32 GPIO4 |
| COM | LED 短脚（阴极） |
| NO | 面包板蓝轨（GND 轨） |
| NC | **不接**（常闭脚，本项目不用；NC 默认导通，用了逻辑反且上电就触发） |

**负载侧（电源从 ESP32 引脚引，继电器触点是无源开关）**
```
ESP32 3V3 ──→ 220Ω ──→ LED长脚(阳极) ──→ LED短脚(阴极) ──→ 继电器 COM
继电器 NO ──→ 面包板蓝轨(与继电器 GND 共地, 一条轨全通)
```
- 3V3/GND 都来自 ESP32 排针（开发板有多个 GND 引脚，也可全部汇到面包板 GND 轨，共地）
- 220Ω 是 LED 限流电阻（套件无 330Ω）：I=(3.3-1.8)/220≈6.8mA，安全
- LED 是压降器件（红/黄 1.8V）不限制电流，必须串电阻，否则烧 LED

**工作逻辑**
- 上电：GPIO4 HIGH → 继电器断开 → LED 不亮（=没按电源键）
- 收到 trigger：GPIO4 拉低 0.4s → 继电器吸合 → LED 亮 0.4s → 灭
- 冷却期：LED 不亮，串口打 [IGNORE]

**测试通过后换真机**：拆掉 LED 和 220Ω，COM/NO 两根线焊到主板电源键焊点（无极性，不分正反），其余不动。
